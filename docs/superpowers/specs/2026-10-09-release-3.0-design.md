# Release 3.0.0 — design

## Goal

Publish the work collected under `### Unreleased` since v2.4.1 as **3.0.0**. A minor release is
not an option: the cycle already breaks source and binary compatibility.

- Source breaks: icons are Compose resources (`TableIcons` returns `DrawableResource`, icon slots
  take `Painter`, `LocalTableHeaderIcons` has no default outside `Table`, iOS and web apps need
  Compose resources packaging); new `UiString` keys break a custom `StringProvider` with an
  exhaustive `when` and no `else`.
- Binary breaks: new parameters change the JVM signatures of `Table`, `EditableTable`, the paged
  `Table`, `TableDimensions.copy` and its constructor; `PinnedSide` changed.
- Visual defaults: selection and stripe colors, typography, font-scaled heights, row motion after a
  sort.

The major release also keeps the promise written into the code at 2.0.0 / 2.1.0: deprecated
members marked "removed in the next major" are removed.

## Decisions taken during brainstorming

- Version 3.0.0.
- Deprecations from 2.0.0 / 2.1.0 are removed. Deprecations added in this cycle go to
  `DeprecationLevel.ERROR` and are removed in 4.0, so users get one release with a warning before
  their code stops compiling.
- A consolidated `migration-3.0.md` guide, following the 2.0 precedent.
- One branch and one PR. Code and docs land in separate commits before a final
  `release: 3.0.0 — …` bump commit. No tag and no GitHub release; the user does those after review.

## 1. API changes

### Removed

- `ExperimentalTableApi` (`table-core/.../ExperimentalTableApi.kt`), deprecated since 2.0.0.
- The deprecated alias block on `TableState` (`state/TableState.kt`), deprecated since 2.1.0,
  together with its "removed in the next major" header comment:

  | Removed                                                             | Use instead                     |
  |---------------------------------------------------------------------|---------------------------------|
  | `columnOrder`, `columnWidths`, `columnContentMaxWidths`, `columnHeaderWidths` | `columns.order`, `columns.widths`, `columns.contentMaxWidths`, `columns.headerWidths` |
  | `autoWidthAppliedForEmpty`, `autoWidthAppliedForData`               | `columns.…` same names          |
  | `resolveColumnWidth`, `moveColumn`, `setColumnOrder`, `resizeColumn`, `setColumnWidths`, `updateMaxContentWidth`, `setColumnWidthToMaxContent`, `recalculateAutoWidths` | the `columns.…` member each `ReplaceWith` names |
  | `selectedIndex`, `checkedIndices`, `selectedCell`, `toggleSelect`, `focusRow`, `toggleCheck`, `toggleCheckAll`, `selectCell` | the `selection.…` member each `ReplaceWith` names |
  | `editingRow`, `editingColumn`, `onRowEditStart`, `onRowEditComplete`, `onEditCancel`, `startEditing`, `tryCompleteEditing`, `completeCurrentCellEdit`, `cancelEditing` | the `editing.…` member each `ReplaceWith` names |

  The migration guide table is generated from the actual `ReplaceWith` expressions, not from this
  summary.

Library code already calls `state.columns.*` / `selection.*` / `editing.*`; no internal caller of
the aliases exists.

### Raised to `DeprecationLevel.ERROR`

- `PinnedSide.Left` / `PinnedSide.Right` (`config/TableSettings.kt`).
- The `TableActiveFilters` overload without `tableData` (`TableActiveFilters.kt`).
- `handleLoadState` (`table-paging/.../LoadStateHandler.kt`).

Messages say the member is removed in 4.0; `ReplaceWith` stays so the IDE quick fix still works.
The `table-paging.md` module doc already calls `handleLoadState` deprecated; its wording is updated
to say it no longer compiles.

### Tests

`PinnedSideTest` asserts `PinnedSide.Left === PinnedSide.Start`, which stops compiling at ERROR. The
test is deleted; `Start` / `End` behaviour is covered by the RTL tests.

## 2. Changelog and docs

- `CHANGELOG.md`: `### Unreleased` becomes `### 3.0.0 — <date>`. A prose paragraph in the style of
  2.0.0 names the release's three themes: accessibility and keyboard, new visual defaults and RTL,
  Compose resources for icons. It links the migration guide. Two bullets are added:
  `Removed (breaking)` for the marker and the `TableState` aliases, `Changed (breaking)` for the
  ERROR deprecations. The section ends with `Compare: [v2.4.1...v3.0.0]`.
- `docs/content/getting-started/migration-3.0.md`, added to `mkdocs.yml` next to
  "Migrating to 2.0". Sections in the order a user hits them:
  1. Icons are Compose resources; packaging for iOS and web.
  2. Removed `ExperimentalTableApi` and `TableState` aliases (Removed → Use instead table).
  3. New `UiString` keys for an exhaustive `StringProvider`.
  4. Members now at ERROR level.
  5. Recompile: changed JVM signatures.
  6. New visual defaults and how to get the old look back where a switch exists
     (`TableDimensions.scaleWithFontSize`, `TableSettings.motion`, `TableColors` /
     `TableDefaults.typography()` overrides).

## 3. Version bump

Per the release checklist, in the `release: 3.0.0 — …` commit:

- `gradle/libs.versions.toml`: `version-name = "3.0.0"`, `version-date`, `android-version-code`
  52 → 53.
- Coordinates in `README.md` and `docs/content/getting-started/installation.md`.
- A `3.0.0 | 2.4.20 | 1.12.0` row in `docs/content/getting-started/compatibility.md`.
- `POM_INCEPTION_YEAR` stays 2026.

## Verification

- `qualityCheck` plus compile tasks for `table-core`, `table-format`, `table-paging` and the samples.
  No full `./gradlew build`.
- `commonTest` / JVM tests for `table-core` and `table-paging`.
- If the detekt or compose-rules baseline lists IDs of removed members, those entries are removed.
- `mkdocs build --strict` if available locally, to catch the new nav entry and broken anchors.
